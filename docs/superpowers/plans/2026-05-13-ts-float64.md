# TypeScript float64 Support Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add float64 (double-precision) support to the TypeScript bindings throughout — NDArrays, meshes, point clouds, curves, all operations, and I/O. Reject mixed dtypes.

**Architecture:** Templatize `wasm_mesh`, `wasm_point_cloud`, `wasm_curves` over `Real`. Add `wasm_ndarray<double>`. Register every Embind function for both `Real = float` (suffix `_float32`) and `Real = double` (suffix `_float64`). TS layer dispatches via `native()[\`fn_${dtype}\`]` and validates dtype match at multi-input boundaries.

**Tech Stack:** C++17 templates, Embind, Emscripten, TypeScript, Float64Array. Build: `npm run build`. Test: `node tests/run.mjs` in `typescript/` dir.

## Strategy notes

- The C++ binding layer has ~40 `.cpp` files with `EMSCRIPTEN_BINDINGS` blocks. Each one needs both `_float32` and `_float64` registration.
- To keep each task atomic and the tree green, we introduce `wasm_mesh_t<Real>` as a new template, keep `wasm_mesh = wasm_mesh_t<float>` as an alias for existing code, and add float64 alongside. Only at the end do we drop the alias.
- Same pattern for `wasm_point_cloud_t<Real>`, `wasm_curves_t<Real>`, `mesh_data<Real>`, `point_cloud_data<Real>`, `curves_data<Real>`.
- Per-module work is independent — order within a phase can be parallelized.

export function assertSameDtype(
  inputs: Array<{ dtype: string }>,
  names?: string[],
): void {
  const first = inputs[0].dtype;
  for (let i = 1; i < inputs.length; i++) {
    if (inputs[i].dtype !== first) {
      const a = names?.[0] ?? "input 0";
      const b = names?.[i] ?? `input ${i}`;
      throw new Error(`dtype mismatch: ${a}=${first}, ${b}=${inputs[i].dtype}`);
    }
  }
}

- `tf.linspace(...)` returns float64 (was float32).
- Operations on mixed-dtype inputs now throw `dtype mismatch: ...` errors. Use `arr.as("float64")` or `arr.as("float32")` to align.

**I/O:**
- `readStl` is always float32 (STL is a 32-bit binary format).
- `readObj` defaults to float64; pass `{ dtype: "float32" }` for float32.
- `writeStl` accepts either dtype mesh and downcasts to 32-bit on write.
- `writeObj` accepts either dtype mesh and writes full precision.

Migration:

```ts
// Before — implicitly float32
const mesh = tf.mesh(faces, [0, 0, 0, 1, 0, 0, 0, 1, 0]);

// After — float64 by default
const mesh = tf.mesh(faces, [0, 0, 0, 1, 0, 0, 0, 1, 0]);

// To keep float32 behavior:
const mesh = tf.mesh(faces, new Float32Array([0, 0, 0, 1, 0, 0, 0, 1, 0]));
```
